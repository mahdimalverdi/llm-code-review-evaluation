Large language model (LLM) assistants can generate code review comments that appear fluent but are unsupported, irrelevant, technically incorrect, non-actionable, or too low-value to justify reviewer attention. Existing evaluations often report correctness, usefulness, acceptance, or hallucination rates, but they less often examine what mitigation strategies lose while reducing problematic comments. A strict filter may remove weak but useful signals; a verifier may improve grounding while adding cost; and a context-quality gate may reduce unsafe automatic review while lowering coverage. This paper presents the design of a controlled empirical study for comparing representative mitigation strategies for problematic LLM-generated code review comments. The planned comparison includes a baseline LLM reviewer, robust prompting, a context-quality gate, post-generation verification, and a hybrid gate-plus-verifier design on paired review instances. We define an operational taxonomy and annotation protocol that separate correctness, grounding, relevance, usefulness, actionability, context quality, and mitigation decision. The planned evaluation combines error-reduction metrics with preservation metrics such as useful comments retained, useful comments wrongly suppressed, review coverage, human escalation, and cost proxies. The contribution is a trade-off-oriented evaluation design that treats mitigation as a workflow decision rather than a single quality score.
